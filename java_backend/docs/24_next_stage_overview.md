# 24 · 一个"真正的项目"还缺什么？

> 衔接 doc 23 结尾留的那句"下一阶段：登录鉴权（JWT）、接口文档（Swagger）、部署上线"。
> 本文回答三个问题：**① 我这样算"完成"了吗？② 黑马 20 小时视频还讲了啥？③ 一个真正的项目应该还有什么？**

## 一、先回答：你"完成"了吗？

**完成了一半——最关键的那一半。** 准确说是完成了后端最核心的**主线地基**：

```
数据库设计 → 三层架构 → CRUD → 事务 → 多表查询 → 分页搜索
```

这条路走通，你已经具备"用 Java 写一个能跑的后端"的完整能力了。这不是小成就——很多人卡在"知道概念但没亲手调通一个项目"，而你是真的一步步把它跑起来了。

**但离"能上线给真人用"还差外围几层**。差别在哪：

| 维度 | 你现在 | 真正上线的项目 |
|------|--------|----------------|
| 谁能用 | 知道网址的人都能改数据 | 必须登录、有权限区分 |
| 跑在哪 | 你自己电脑 localhost，关机就没 | 云端服务器 24 小时开机 |
| 代码存哪 | 本地文件夹，改坏了没存档 | Git 版本管理 + GitHub 备份 |
| 接口说明 | 自己在 test.http 里手动测 | 自动生成的接口文档给别人看 |
| 出了错 | 默认的 500 页面 | 统一的错误提示 + 日志排查 |

**一句话：你建好了"房子的主体结构"，但还没装门锁、没通电、没对外挂牌。** 接下来几块就是把房子变成"能住人、能营业"。

## 二、黑马 20 小时视频还讲了什么

你跟着学的这套（Controller/Service/Mapper 三层 + MyBatis + 事务）是视频的**前半段核心**。视频后段通常会补这些（不一定全有，看具体版本）：

1. **登录认证 JWT** —— 就是下面第三节要讲的"门锁"
2. **拦截器 / 过滤器** —— 在每个请求进来前统一检查"你有没有登录"
3. **全局异常处理** —— 把 try-catch 收拢到一处，不再每个接口重复写
4. **AOP（切面编程）** —— 把"日志、权限"这类横切逻辑抽出来统一处理
5. **文件上传** —— 传图片/文件到服务器
6. **分页插件（PageHelper）** —— 你手写的 LIMIT 分页，有现成插件能一行搞定
7. **Redis 缓存** —— 把频繁查询的数据放内存里，加速
8. **Swagger / Knife4j 接口文档** —— 见第三节
9. **部署（Linux + Docker）** —— 见第三节

> 注意：这些是"后续扩展"，不是"你必须全学完才算会"。主线你已经走完了，剩下的按需补即可。

## 三、一个真正的项目，核心还差这四块

### 1️⃣ 登录鉴权（JWT）—— "门锁"

**问题**：你现在 `/borrow/{bookId}/{readerId}` 这种接口，任何人知道网址就能直接调用，把书借走、把数据删掉。真实系统不能这样——得先登录。

**JWT（JSON Web Token，JSON 令牌）** 是当下最主流的做法，思路像一个**会员卡**：

1. 用户先登录（输账号密码）
2. 服务器验证通过，发一张"会员卡"——就是一个**令牌（token）**，一串加密签名的字符串，里面写着"你是谁、有效期多久"
3. 之后每次请求，客户端把这张卡**放在请求头里**带过去
4. 服务器每次验卡：卡是真的吗？过期了吗？——通过才放行

**关键特点**：服务器**不存**这张卡（无状态），全靠卡上自带的签名防伪造。你改卡上任何一个字，签名就对不上，直接失效。

> 配套的还有"**拦截器（Interceptor）**"：在 Controller 之前拦一道，统一验 token，不用每个接口都写一遍"登录了吗"。

---

### 2️⃣ 接口文档（Swagger）—— "菜单"

**问题**：你现在接口是自己写的，自己知道怎么调。但真实项目是**团队**协作——前端要调你的后端，同事要看你提供了哪些接口。总不能口头说"有个 /borrow 接口，传 bookId 和 readerId"。

**Swagger**（就是一套自动生成接口文档的工具）做三件事：

1. **自动扫描**你的代码，生成一张"接口菜单"网页：列出所有接口、每个接口的路径、参数、返回值
2. **还能在线调试**：直接在网页上填参数、点发送，看返回结果（省得你在 test.http 里手敲）
3. 前后端对接口靠它，不靠嘴说

> 你只要在 Controller 上加几个注解（`@Operation`、`@Parameter` 之类），Swagger 就自动生成文档。国产版叫 **Knife4j**，黑马视频里常用，界面更好看。

---

### 3️⃣ 部署（deploy）—— "对外营业"

**你现在**：程序跑在 `localhost:8080`，只有你这台电脑能访问，关机就没了。

**部署** = 把程序放到一台**云端服务器**上，让它 7×24 小时运行，别人通过网络访问。形象点：**把店从你自己卧室，搬到街上一个对外营业的门面。**

具体流程大致是：

```
① 打包：把整个项目打成 1 个 jar 文件
② 买台云服务器：阿里云/腾讯云，一台 24 小时开机的 Linux 电脑
③ 把 jar 传上去，装好 JDK，跑起来
④ 给它配个公网 IP / 域名，别人就能访问了
```

常见的配套工具：

- **Linux**：服务器基本都是 Linux 系统，要会一点基本命令（`ls`、`cd`、`scp` 上传文件……）
- **Docker**：把程序和它的环境"装进一个箱子"，到哪都能原样跑，避免"我电脑上能跑，服务器上跑不起来"
- **Nginx**：反向代理，把域名指到你的程序，顺便处理 HTTPS 证书

> 对学习来说，可以先在阿里云搞台便宜的"学生机"，或者用免费的方案（如 Railway、Render、内网穿透）先把项目弄上线体验一把，不一定要一开始就啃 Linux+Docker。

---

### 4️⃣ Git / GitHub —— "存档 + 云备份"

这两个经常一起提，但**不是一回事**：

- **Git**：一个**版本管理工具**（本地跑的命令）。它给你的代码建"存档点"，每次提交都记一笔快照，可以：
  - 回退到任何一次历史版本（改坏了能救回来）
  - 看每次改了什么、谁改的
  - 开**分支**：一条主线稳定跑，另开一条支线开发新功能，做完再合并

- **GitHub**：一个**网站**（代码托管平台）。把你本地的 Git 仓库**推（push）到云端**存着，作用是：
  - **备份**：电脑丢了代码还在
  - **协作**：多人拉取同一份代码一起改
  - **展示**：找工作/实习时，GitHub 就是你的"代码作品集"

**关系**：Git 是"记笔记的习惯"，GitHub 是"把笔记存到云上的网盘"。

> 对你现在尤其有用的一个场景：**代码托管 + 备份**。你的 java_enter 整个学习项目，push 到 GitHub 后，就算电脑出问题也不怕丢，还能随时给别人看你的成长轨迹。

## 四、建议的下一步顺序

按"投入小、见效快、对你后续帮助大"来排：

| 顺序 | 学什么 | 为什么先学 |
|------|--------|-----------|
| 1 | **Git + GitHub** | 半小时就能上手，立刻能备份你的全部代码，性价比最高 |
| 2 | **JWT 登录鉴权** | 补上项目最明显缺的"门锁"，让项目更像真的 |
| 3 | **Swagger 接口文档** | 顺手，几个注解搞定，团队协作标配 |
| 4 | **部署上线** | 最后做，把项目真正搬到云端，体验"上线"的完整闭环 |

> 我的建议是：**先花半天把 Git + GitHub 弄通，把你 java_enter 整个目录备份上去**，再回来补 JWT。因为代码托管是"磨刀"，学会之后以后每做一个项目都用得上，而且是零风险（不动你的代码逻辑）。
