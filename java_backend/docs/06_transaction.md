# 06 · 事务 —— 让一组操作"要么全成，要么全失败"

> 目标：理解事务的作用、ACID 四大特性、并发问题和隔离级别。
> 前置：读完 01~05，会用增删改查。

---

## 零、事务是什么？为什么需要它

一句话：**事务 = 把一组操作打包成一个"整体"，要么全部成功，要么全部失败（回滚），不允许"一半成功一半失败"。**

### 经典例子：银行转账

A 转 100 块给 B，数据库要干两步：

1. A 的余额 −100
2. B 的余额 +100

这两步**必须一起成功**。如果第 1 步成功了、第 2 步却失败（比如宕机），那 100 块就凭空消失了。事务就是保证：**要么两步都成功（提交），要么都撤销（回滚），绝不留一半。**

> 事务在以后后端开发里**极其重要**——Spring 里写"扣库存 + 生成订单"这种多步操作，全都得包在事务里。所以这块要理解透。

## 一、事务操作：手动控制提交/回滚

MySQL 默认是**自动提交**（每条语句执行完自动生效，相当于每条都自动 COMMIT）。要手动把多步捆成一个事务：

```sql
START TRANSACTION;   -- 开始事务（也可以写 BEGIN;）

-- 这里写你的一堆操作……
UPDATE account SET money = money - 100 WHERE name = 'A';
UPDATE account SET money = money + 100 WHERE name = 'B';

COMMIT;              -- 都成功，提交（永久生效）
-- 或者
ROLLBACK;            -- 出错了，回滚（撤销到事务开始前）
```

### 查看/修改自动提交

```sql
SELECT @@autocommit;    -- 查：1=自动提交（默认），0=手动
SET @@autocommit = 0;   -- 关掉自动提交（之后需要手动 COMMIT）
```

> ⚠️ 记住这个习惯：**开事务 → 操作 → COMMIT 或 ROLLBACK**。忘了 COMMIT 的话，事务一直挂着不生效。

## 二、ACID 四大特性（事务的"四个保证"）

| 特性 | 意思 | 一句话 |
|------|------|--------|
| **A**tomicity 原子性 | 事务是不可分割的最小单元，要么全做、要么全不做 | 不能"做一半" |
| **C**onsistency 一致性 | 事务前后，数据都处于合法状态 | 转账前后总金额不变 |
| **I**solation 隔离性 | 并发执行的事务之间互不干扰 | 各干各的 |
| **D**urability 持久性 | 一旦提交，数据永久保存（断电也不丢） | 提交就落地 |

这四点面试**常考**，记住英文单词开头字母 **ACID** 就能串起来。

## 三、并发事务会出什么问题

多个事务同时跑，互相"看见"对方会导致三种问题：

### 1. 脏读（Dirty Read）

读到了别人**还没提交**的数据（别人后来回滚了，你就读到了假数据）。

### 2. 不可重复读（Non-repeatable Read）

同一个事务里，**两次读同一行，值不一样**——因为中间有别人改了并提交了。

### 3. 幻读（Phantom Read）

同一个事务里，**两次查询，行数不一样**——因为中间有别人插入了新行（像"幻影"一样多出来了）。

> 记法：**脏读 = 读到脏（没提交）数据；不可重复读 = 值变了；幻读 = 行数变了。**

---

## 四、隔离级别（解决并发问题的"程度开关"）

隔离级别越高，越安全，但并发性能越差。四种级别：

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---------|:---:|:---:|:---:|
| `READ UNCOMMITTED`（读未提交） | ✅会 | ✅会 | ✅会 |
| `READ COMMITTED`（读已提交） | ❌ | ✅会 | ✅会 |
| `REPEATABLE READ`（可重复读，**MySQL 默认**） | ❌ | ❌ | ✅会 |
| `SERIALIZABLE`（串行化） | ❌ | ❌ | ❌ |

- MySQL 默认是 **`REPEATABLE READ`**（解决了脏读和不可重复读）。
- 最安全的是 `SERIALIZABLE`，但性能最差，基本不用。

### 查看 / 设置隔离级别

```sql
SELECT @@transaction_isolation;                              -- 查看
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;      -- 设置当前会话级别
```

## 五、动手练习

1. `START TRANSACTION;` 插入一条数据 → `COMMIT;` → 再查，看数据在不在。
2. `START TRANSACTION;` 插入一条数据 → `ROLLBACK;` → 再查，看数据被撤销没有。
3. `SELECT @@autocommit;` 和 `SELECT @@transaction_isolation;`，看看当前默认值是多少。

> 练习重点体会：**COMMIT = 落地，ROLLBACK = 撤销**。第 2 题里"插入后又消失"的那条数据，就是事务回滚的威力——将来写"转账/下单"这类多步操作，全靠它兜底。

---

## 怎么用（一句话）

事务 = 把多步操作捆一起，`START TRANSACTION` 开头、`COMMIT`（成功）或 `ROLLBACK`（失败）结尾。核心记两句：**要么全成要么全败**（原子性），以及 **ACID 四特性 + 四种隔离级别**（面试重点）。
