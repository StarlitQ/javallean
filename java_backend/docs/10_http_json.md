# 10 · HTTP 与 JSON —— 前后端怎么对话

> 目标：搞懂 HTTP（请求/响应）和 JSON（数据格式），这是理解 Spring Boot 的前提。
> 前置：不需要写代码；读完 00（后端全景）更好，脑子里有"前端/后端/数据库"的图。

---

## 零、为什么现在学这个

00 里你知道了"一个网站怎么跑起来"：浏览器（前端）→ 后端 → 数据库。现在细化中间那环——**前端和后端之间，到底靠什么对话？**

答案就两个词：**HTTP（对话规则）+ JSON（对话用的数据格式）**。

记住一句话，后面学 Spring Boot 全靠它兜底：

> **Spring Boot 的本质 = 接收 HTTP 请求 → 处理 → 返回 JSON。**

所以先把 HTTP 和 JSON 搞明白，Spring Boot 就是"用 Java 来实现这个流程"而已。

---

## 一、HTTP —— 前后端对话的规则

**HTTP（HyperText Transfer Protocol，超文本传输协议）**：浏览器和服务器之间约定好的"一问一答"规则。

### 请求 / 响应模型

客户端（浏览器）发**请求**，服务器回**响应**。一问一答，答完就断。

打比方：HTTP 就像**寄信**。你寄一封信（请求），对方回一封信（响应）。

### 一个请求里有什么（四要素）

| 要素 | 是什么 | 打比方 |
|---|---|---|
| **方法 Method** | 想干什么 | 信封上写"取件 / 寄件" |
| **URL** | 找谁、哪个地址 | 收件地址 |
| **请求头 Headers** | 附加信息（格式、身份等） | 信封上的备注 |
| **请求体 Body** | 带的数据（POST 时才用） | 信纸里的内容 |

#### 方法（对应增删改查，跟 SQL 一模一样）

| 方法 | 含义 | 对应 SQL |
|---|---|---|
| **GET** | 取数据（查） | SELECT |
| **POST** | 提交新数据（增） | INSERT |
| **PUT** | 改数据（改） | UPDATE |
| **DELETE** | 删数据（删） | DELETE |

> 记忆：**HTTP 的四种方法，就是 SQL 增删改查在"前后端对话"里的翻版。** 以后写后端接口，就是"收到一个 GET 请求 → 去查数据库 → 返回结果"。

#### URL（Uniform Resource Locator，统一资源定位符）

就是"地址"。比如 `http://localhost:8080/user?id=1`：

- `http://` 协议
- `localhost:8080` 主机 + 端口（"哪台机器、哪个门"）
- `/user` 路径（找哪个资源）
- `?id=1` 参数（附加条件）

### 一个响应里有什么

| 要素 | 是什么 |
|---|---|
| **状态码 Status Code** | 干得怎么样（成功 / 失败 / 啥原因） |
| **响应体 Body** | 返回的数据（通常是 JSON） |

#### 常见状态码（记住几个就够）

| 状态码 | 含义 | 打比方 |
|---|---|---|
| **200** | OK，成功 | "收到，办好了" |
| **404** | Not Found，找不到 | "没这个人" |
| **500** | 服务器内部出错 | "我这出故障了" |
| **400** | 请求有错 | "你写的东西我看不懂" |
| **401 / 403** | 没登录 / 没权限 | "先登记" / "你没资格" |

> 以后调后端接口，看到 404 / 500 就知道去哪查：404 是"地址/资源不对"，500 是"后端代码报错了"。

### 关键理解：无状态

HTTP 每次请求都是**独立**的，服务器不记得"你上次是谁"。那怎么记住登录状态？靠 cookie / session / token 这些机制——先了解个名词，Spring Boot 里会用到。

## 二、JSON —— 对话用的数据格式

**JSON（JavaScript Object Notation，JavaScript 对象表示法）**：一种用**纯文本**表示数据的格式，前后端都拿它传数据。

### 长什么样

```json
{
  "name": "张三",
  "age": 20,
  "gender": "M",
  "tags": ["篮球", "游戏"],
  "dept": { "id": 2, "name": "management" }
}
```

规则就几条：

- 一堆**键值对**，键必须用**双引号**包起来
- 值可以是：字符串、数字、布尔、数组 `[]`、对象 `{}`、`null`
- 逗号分隔，可以层层嵌套

> 你一看就熟：**JSON 就像 Java 里的 Map + List + 对象的组合，只不过它是纯文本，任何语言都能读。**

### 为什么用它

1. **人和机器都能读懂**（不像二进制）
2. **几乎所有语言都支持**解析（Java、Python、JS…）
3. 前后端统一约定：后端返回 JSON，前端解析 JSON，两边都省事

### 和 Java 的关系（重点）

后端里，Java 对象（比如 `User` 类）和 JSON 之间要**互相转换**：

- Java 对象 → JSON（返回给前端）：叫**序列化**
- JSON → Java 对象（接收前端数据）：叫**反序列化**

Spring Boot 里这个转换是**自动**的（用 Jackson 库），你几乎不用手写。现在知道有这么回事就行。

## 三、一个完整的"对话"例子

浏览器要查"id=1 的用户"，整个过程：

```
浏览器 → 后端：
  请求：GET /user/1

后端 → 浏览器：
  响应：200 OK
  响应体（JSON）：{ "id": 1, "name": "张三", "age": 20, "dept_id": 2 }
```

就这么简单。你之前 MySQL 里 `SELECT * FROM user WHERE id=1` 查出来的那一行，包装成 JSON，通过 HTTP 响应返回给前端——**这就是后端干的活**。

## 四、动手练习（不用写代码）

1. 打开任意网页，按 **F12** 打开开发者工具，切到 **Network（网络）** 标签。
2. 刷新页面，点任意一条请求，看它的 **Method**（GET/POST）、**Status**（状态码）。
3. 找到一条返回 JSON 的请求（`Preview` 标签能看 JSON 结构），体会"后端返回的数据长啥样"。

> 练习重点：**亲眼看到"请求 = Method + URL + 状态码，响应 = 状态码 + JSON"**。这个图印在脑子里，Spring Boot 就入门一半了。

---

## 怎么用（一句话）

HTTP = 前后端对话的规则（请求：方法 + URL + 数据；响应：状态码 + JSON）。JSON = 纯文本数据格式，前后端通用的"普通话"。Spring Boot 就是"接收 HTTP 请求 → 处理 → 返回 JSON"。
